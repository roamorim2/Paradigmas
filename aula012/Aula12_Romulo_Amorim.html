3.1 No passo a passo, o que cresce na recursão comum e não cresce na recursão em cauda? Por quê?
Na recursão comum cresce a quantidade de chamadas esperando para terminar. Na recursão em cauda isso não acontece porque a chamada recursiva é a última operação.

4.1 Cole aqui as suas três funções (tamanho, soma-quadrados e pares).
(define (tamanho lis)
  (if (null? lis)
      0
      (+ 1 (tamanho (cdr lis)))))

(define (soma-quadrados lis)
  (if (null? lis)
      0
      (+ (* (car lis) (car lis))
         (soma-quadrados (cdr lis)))))

(define (pares lis)
  (cond ((null? lis) '())
        ((even? (car lis))
         (cons (car lis) (pares (cdr lis))))
        (else
         (pares (cdr lis)))))

// Prática 6b - Lambdas e Streams em Java (Sebesta 15.10, p. 676)
// Cole em https://onecompiler.com/java
import java.util.*;
import java.util.function.*;

public class Main {
    record Produto(String nome, double preco) {}

    public static void main(String[] args) {
        Function<Integer, Integer> f = x -> x + 2;
        Function<Integer, Integer> g = x -> 3 * x;
        System.out.println(f.compose(g).apply(4));     // f(g(4))
        System.out.println(f.andThen(g).apply(4));     // g(f(4))

        List<Produto> produtos = List.of(new Produto("Teclado", 150), new Produto("Mouse", 80),
                                         new Produto("Monitor", 900), new Produto("Cabo", 35));
        double caros = produtos.stream()
            .filter(p -> p.preco() > 100)
            .mapToDouble(Produto::preco)
            .sum();
        System.out.println(caros);
        System.out.println(produtos.stream().map(p -> p.nome().toUpperCase()).sorted().toList());
    }
}
6.1 somador(10) já terminou de executar quando mais10(5) é chamado. Como a função devolvida ainda "lembra" o 10?
A função devolvida lembra o valor 10 porque usa um closure, que guarda o valor da variavel do ambiente onde foi criada mesmo depois que somador(10) termina.
6.2 Por que f.compose(g).apply(4) e f.andThen(g).apply(4) deram resultados diferentes? Qual deles corresponde ao compor(f, g) da Prática 1?
Os resultados foram diferentes porque a ordem de execução das funções muda. O compose executa primeiro g e depois f, enquanto o andThen executa primeiro f e depois g. O f.compose(g) corresponde ao compor(f, g) da Prática 1, pois ambos calculam primeiro g(x) e depois f.
